# 基线维护指南

## 仓库结构

| 路径 | 内容 |
| :--- | :--- |
| `copier.yml` | 创建项目时的问题；`_skip_if_exists` 列出项目自有文件（同步时不覆盖） |
| `template/` | 项目模板。`.jinja` 后缀的文件会渲染变量，其余原样复制 |
| `template/.baseline/managed-files.txt` | 基线托管文件，项目内修改会被提交钩子拦截 |
| `template/.ai/` | AI 规则与 Skills 源文件 |
| `template/scripts/` | 门禁、脚手架、发布脚本 |
| `bin/selftest.sh` | 自测 |
| `tools/server-hooks/` | 服务端钩子 |
| `proposals/` | 改进提案 |

## 文件归属

| 类型 | 例子 | 同步基线时 |
| :--- | :--- | :--- |
| 基线托管 | `scripts/**`、`.ai/rules/**`、`.ai/skills/**`、`docs/_templates/**`、`.githooks/**`、Lint 配置 | 直接覆盖；项目内不能改 |
| 项目自有 | 业务源码、`contracts/`、`db/`、`docs/` 中的项目文档、`.ai/project/` | 不覆盖 |
| 共同维护 | `backend/pom.xml`、`frontend/package.json`、`copier.yml` 中未列出的其他文件 | Copier 三方合并，冲突时人工处理 |

新增模板文件时，先判断它属于哪一类，并同步更新 `managed-files.txt` 或 `copier.yml` 的 `_skip_if_exists`。

## 修改规则或 Skill

1. 规则写在 `template/.ai/rules/<编号>-<名称>.md`，文件头必须有 `id`、`title`、`scope`（`always` / `glob` / `requested`）、`summary`，`glob` 规则还要有 `globs`。
2. `always` 规则会全文进入 `AGENTS.md`，要克制：`AGENTS.md` 超过 150 行时编译失败。
3. 写规则要写"做什么、不做什么、怎么验证"，不写原理和背景。

## 发布基线版本

```bash
bin/selftest.sh all          # 三种画像全部通过（需要 Docker，约 5 分钟）
# 更新 CHANGELOG.md：变化、项目升级时需要注意的事项
git commit -am "chore: 发布 v0.2.0" && git tag -a v0.2.0 -m v0.2.0 && git push --follow-tags
```

版本号：主版本表示流程或规范有不兼容变化（需要培训）；次版本表示新增规则、Skills 或检查；修订版本表示修正错误。

`copier update` 依赖基线仓库的 Git 标签，基线仓库必须是 Git 仓库并打了标签，项目才能同步升级。

## 处理改进提案

各项目把踩坑经验、Skill 改进写成 `proposals/<日期>-<短名>.md`（格式见 `proposals/README.md`）。维护组每月评审一次，采纳的进入下一个次版本，在 `CHANGELOG.md` 中注明来源项目。
