# 运维 / 实施指南

## 交付包

每个版本由技术负责人交付一个 `<项目>-<版本>.tar.gz`，结构固定：

```text
<项目>-v1.3.0/
├── app/              # 后端 jar、前端静态文件
├── images/           # 镜像离线包（amd64 与 arm64，按需提供）
├── db/<方言>/        # 本版本的全部迁移脚本
├── config/           # 配置模板
├── release-notes.md  # 新功能、修复、数据库变更、配置项变化
├── deploy-guide.md   # 全新部署
├── upgrade-guide.md  # 从每个在用版本升级、停机时间、回退方式
└── checksums.txt
```

收到后先校验：`shasum -a 256 -c checksums.txt`。

## 部署与升级的固定规则

1. **数据库迁移是独立步骤**，应用启动时不会自动执行。执行前必须备份数据库。
2. 迁移命令：`java -jar app/<项目>-app.jar --spring.profiles.active=migrate,<方言>`（PostgreSQL 不加方言）。
3. 应用启动：`--spring.profiles.active=prod,<方言>`，数据库连接通过环境变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD` 传入；同一套系统部署多个后端实例时，每个实例设置不同的 `APP_WORKER_ID`（0～1023）。
4. 按 `upgrade-guide.md` 中对应你所在版本的步骤操作；手册里没有你的起始版本时，停止并联系技术负责人。
5. 不修改交付包中的脚本和程序。

## 部署回执

每次部署或升级后，把以下信息发给项目工程师或技术负责人：

| 项 | 示例 |
| :--- | :--- |
| 客户现场 | B 园区 |
| 版本 | v1.3.0（升级前 v1.2.0） |
| 时间 | 2026-10-20 22:00～22:40 |
| 结果 | 成功 / 失败 |
| 遇到的问题 | 迁移耗时 12 分钟，超出手册预计 |

回执会登记到项目的客户版本台账，下一个版本的升级测试以台账为准，所以**每次都要回填**。
