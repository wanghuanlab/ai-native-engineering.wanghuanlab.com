# ADR-0001：错误响应采用 RFC 9457 ProblemDetail，成功响应不包信封

| 项 | 内容 |
| :--- | :--- |
| 状态 | 已采纳（基线默认） |
| 日期 | 2026-10-15 |
| 决策人 | 基线维护组 |

## 背景

常见做法是所有响应都包一层 `{code, message, data}`。这样 HTTP 状态码失去意义，OpenAPI 契约里每个接口都要声明泛型包装，生成的前后端代码也更难用。

## 决策

- 成功时直接返回业务对象，用 HTTP 状态码表达结果（200、201、204）。
- 失败时返回 `application/problem+json`（RFC 9457），在标准字段之外增加：
  - `code`：业务错误码，如 `A0400`、`B9901`，前端据此做分支处理；
  - `traceId`：追踪编号，与日志和响应头 `X-Trace-Id` 一致；
  - `errors`：字段校验错误列表（仅 400）。
- 统一由 `common` 模块的 `GlobalExceptionHandler` 输出；业务代码抛出 `BizException(错误码)`。

## 备选方案

- 统一信封：与现有部分项目的习惯一致，但上述问题无法解决。客户集成方明确要求信封时，可以在网关层转换。

## 影响

- 前端 `api-client` 的 `request` 函数把非 2xx 响应转换为 `ApiError`（含 `code`、`traceId`）。
- 现有项目迁移到基线时，接口风格需要在 L 级设计中说明。
